PUD query model (matches the code in core/hpp/infrastructure, 2026)

Overview

The progressive unfolding database (PUD) is one tree of resolvents under axiom and
conjecture roots. Each open leaf carries bindings (union-by-size bind map), a
structure watch keyed by body-goal id, and a map from body-goal id to multi-headed
query id. Solving is unit-first random expansion via pud_solver.

Terms and bindings

- Expressions in the database are unframed const expr* with global variable indices.
- At query time, pud_replayer lifts axiom heads and replay paths using the callee
  frame offset (the leaf's LVC).
- ubs_bind_map owns transient parents/classes, supports find, equate (returns
  displaced value when both sides were bound), instantiate, and persist() && into
  pud_ubs_state. Absorbed equivalence classes are erased from the map.
- pud_unifier memoizes identical pairs and functor-pair work; pud_normalizer and
  pud_exporter memoize per traversal.

Search stack (no separate query tree)

- pud_replay: { pud_node_id node, uint32_t frame_offset, pud_ubs_state ubs_state }.
- pud_replayer: enter(caller_state, goal, frame_offset, axiom_root) and
  descend(replay, child) replay substitutions along the path to a candidate.
- pud_mhws: witness search under one outgoing edge (DFS, resumable).
- pud_mhcs: at most one candidate per axiom for a goal; choice point = two witness
  searches; self-witness = candidate path is a single leaf.
- pud_axiom_groups: axiom roots live in a group; dependencies form a DAG. A query
  opened in group G may use candidate roots from G and every group G depends on,
  never from a group that depends on G. A query sees only the roots its group
  could see when it was opened, so once a group's roots are read, no group it
  sees may gain members or dependencies (debug-asserted).
- pud_mhq: one head per body goal; try_open(group, ...) stores candidates in
  dependency-then-registration order; admits only when at least one candidate
  exists; pushes unit heads onto an injected deque when a head drops to one
  candidate; check_exhausted(head) once its last candidate is refuted.

Node lifecycle

- Made (pud_node_maker): tree tables written. make_root(rule, group) also makes
  the root an axiom of its group; make_child(parent, call_site, delta) puts the
  child in its parent's group. A node is a leaf from birth.
- Active: has pud_active_state { bindings, watch, queries } and holds its
  queries. Active leaves are the frontier. An interior node is active only while
  its children are being activated: the leaf just unfolded by expand, or nodes
  on the way down while active state is propagated from the roots after a load.
- Interior (pud_unfolder::unfold): call site, children, live-child count.
- Refuted (pud_leaf_refuter::refute): a leaf marked refuted, propagated up the
  tree, deactivated, and every leaf holding a query that deactivation exhausted
  refuted in turn. Interior holders are left alone: their children inherit the
  exhausted query and arrive refuted. An interior node is dead when every child
  is.

Loading axioms

- Make every root of a group and of every group it depends on, then activate
  each root (pud_root_activator::activate_root), refuting those that arrive
  refuted. Two plain loops; nothing takes a batch.

Activation

- pud_binder applies child added_substitutions onto the parent bind map.
- pud_structure_watcher: goals indexed by pud_body_goal_id; a goal changes when
  any of its watched reps is instantiated or two of its reps merge.
- pud_query_opener::open(leaf, bindings, goal): one query over the axioms the
  leaf's group sees, in the leaf's environment.
- pud_query_forker::fork(inherited, leaf, bindings, goal): an inherited query
  forked into the leaf's environment for a goal whose structure changed.
- pud_child_activator: the child inherits every parent query but the call
  site's, forks each changed goal, opens a query for each goal of its own, then
  holds every query.
- pud_root_activator: opens a query per goal and holds them.
- Both return whether the node arrived refuted: a goal whose query failed to
  open or fork, or an inherited query already exhausted.

Query ownership

- pud_query_holders maps head id -> { goal id, set of leaf ids holding it }.
- Nodes acquire heads in pud_root_activator / pud_child_activator and release them in
  pud_node_deactivator, which also invalidates the node as a witness and returns
  the nodes left holding a query without a candidate.
- When the last holder releases a head, mhq::remove is the only removal path.

Expansion

- pud_expander::expand(leaf, goal): pud_resolver yields one delta per candidate;
  pud_node_maker makes a child per delta; pud_unfolder makes the leaf interior;
  each child is activated and refuted at once if it arrives refuted; the leaf is
  deactivated and every leaf that strands is refuted. Returns
  pud_frontier_change { offspring: live children, refuted: every leaf refuted }.

CLI

- atlas pud <chc> -g "<body goals>" [--head "<answer template>"] runs the manifest
  solver over file axioms and prints materialized answers.

Deprecated concepts (do not reintroduce)

- Separate query trees, om_interval maps, FPA record/replay, transient bind-map
  facades, destructor-owned query heads, duplicate candidate storage in mhq,
  watch-head ids separate from goal ids, dual solver front-ends.

Performance note (depth 22 shared DAG, see /tmp/pudprobe in dev trees)

After memoization: unify ~0.002 ms, normalize ~0.006 ms, detect_cycle ~0.003 ms
(vs ~32 ms / ~357 ms / ~16 ms before).
